    ¿De qué se trata?

    Una transferencia parece sencilla, pero se debe descontar de una cuenta y sumar en otra como una sola operación, aunque lleguen muchas solicitudes a la vez o la red falle. Esta aplicación muestra cómo lograrlo.

    Atomicidad

    El débito y el crédito se confirman en una misma transacción: ocurren los dos o no ocurre ninguno.

    Sin doble gasto

    El saldo se verifica y se descuenta en una sola sentencia SQL, así dos pagos simultáneos no pueden gastar el mismo dinero.

    Idempotencia

    Cada pago lleva una clave única. Si el cliente reintenta, recibe la misma transferencia en lugar de un segundo cobro.

    Partida doble

    Cada transferencia crea un débito y un crédito que suman cero, lo que deja un historial que se puede auditar.

    Cómo funciona una transferencia

    Esto ocurre cada vez que pulsa «Enviar».

    1. AutenticaciónLa API valida el token JWT que recibió al iniciar sesión.
    2. Registro únicoInserta la transferencia. La base rechaza una clave de idempotencia repetida.
    3. Movimiento de saldosActualiza las cuentas siempre en el mismo orden, para evitar interbloqueos.
    4. ConfirmaciónGuarda los dos asientos y confirma. Ante cualquier fallo, todo se revierte.

    La plataforma que la ejecuta

    Toda la infraestructura se define con Terraform y se despliega por ambientes desde GitHub Actions, sin service principal ni secretos de Azure en el repositorio.
